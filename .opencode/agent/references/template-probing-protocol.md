# 模板探测流程（Template Probing）

当优先级 1（用户已上传模板）不满足时，对用户提供的源文件（招标文件、附件包等）执行以下探测：

**如果 bid-analysis 已执行且 `.worktree/index.json` 中存在 `template_findings` 字段，优先使用其报告结果，避免重复扫描。**

**如果 `file-triage.json` 已存在**（bid-analysis Step 0 已执行），优先从 `tender_attachment` 类别中搜索模板文件，大幅减少扫描范围。

**探测位置（按优先级）：**

1. **同目录下独立文件** — 检查源文件所在目录是否有名称含 "格式"/"模板"/"空白" 的 .docx/.doc 文件（如 `投标文件格式.docx`、`响应文件模板.docx`）
2. **压缩包** — 如果目录下有 zip/rar 包（招标文件常以压缩包发放），解压后搜索模板文件
3. **文档内嵌章节** — 对源文件做结构扫描，查找以下章节标题（不要求精确匹配措辞）：
   - "投标文件格式" / "投标（响应）文件格式"
   - "投标文件编制格式"
   - "格式及组成" / "响应文件组成及格式"
   - 位于文档末尾附件/附录中的格式模板

**探测结果处理：**

- **找到独立模板文件** → 创建工作副本（保护原件），将副本路径记录到 `.worktree/index.json` 的 `target_doc`，向用户确认后使用（走路径 A：格式保真复制）
- **找到内嵌格式章节** → 提取该章节确定的目录结构和格式要求，以此为骨架创建目标文档（保留章节编号、表格框架）
- **均未找到** → 进入优先级 3 或 4
- **发现多个候选** → 向用户展示候选列表，请用户选择

**探测必须在分析或撰写开始之前完成。**
